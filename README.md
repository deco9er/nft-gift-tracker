# Трекер NFT-подарков

**Русский** · [English](README.en.md)

Telegram-бот для мониторинга перепродажи коллекционных подарков в Telegram Market. Один процесс обновляет каталог, проверяет счета Crypto Pay и управляет доступом к форуму.

Команды `/start` и `/live` открывают свежие лоты с повторной проверкой цены и доступности. Команда `/gifts` открывает весь каталог Telegram Market. **Фильтры** позволяют совместить коллекцию, цену листинга, тип владельца, рейтинг и категорию флора. Категории флора в TON/GRAM: до 10, свыше 10 до 50, свыше 50 до 1500. Флор считается как минимальная цена в GRAM среди загруженных активных лотов коллекции с фиксированной ценой. Аукционы и лоты только в Stars в этот расчёт не входят. **Сортировка** доступна по названию, номеру, цене, флору и рейтингу. Кнопка ↻ обновляет страницу и прогресс обхода.

Команда `/changes` показывает новые листинги и изменения цены. После `/group` бот публикует их в общей ленте и закреплённых ветках **Дешёвые**, **Средние** и **Дорогие**. В группе кнопка **Занять лот** закрепляет активный лот за первым участником с действующим доступом и публичным `@username`. В публикации отображается, кто занял лот. Ссылка на продавца и подарок отправляется этому участнику в личку. Бронь действует в трекере. Перед отправкой и при бронировании бот проверяет лот, цену и владельца на маркете.

## Подготовка

Скачайте ZIP из [релиза](https://github.com/deco9er/nft-gift-tracker/releases) или клонируйте репозиторий.

```bash
git clone https://github.com/deco9er/nft-gift-tracker.git
cd nft-gift-tracker
```

Понадобится Python 3.10–3.14. Для новой установки скопируйте `.env.example` в `.env` и задайте:

- `BOT_TOKEN` от [@BotFather](https://t.me/BotFather). Для Premium-эмодзи бот должен принадлежать вашему Premium-аккаунту.
- `API_ID` и `API_HASH` из раздела API development tools на [my.telegram.org](https://my.telegram.org). Они нужны для чтения официального маркета от лица пользовательского аккаунта.
- `ADMIN_ID` со списком числовых Telegram ID администраторов через запятую.
- `CRYPTO_PAY_API_TOKEN` из приложения Crypto Pay. С `CRYPTO_PAY_TESTNET=1` используется отдельный токен @CryptoTestnetBot и отдельная база доступа. Основная сеть используется по умолчанию. [Документация Crypto Pay](https://help.cr.bot/en/articles/10279948-crypto-pay-api)

Для ежедневной работы запускайте `parser/catalog_bot.py`. Дублирующий запуск в той же папке блокируется. На другом сервере используйте тот же токен только после остановки старой копии.

При переносе остановите бот и перенесите `.env`, `market.session`, `catalog.sqlite3` и используемую базу доступа `access.sqlite3` или `access-testnet.sqlite3`. Если рядом остались файлы `-wal`, переносите их вместе с соответствующей базой. Виртуальное окружение создаётся на новом сервере. Ограничьте доступ к конфигурации, сессии и базам пользователем, от которого запущен бот.

## Windows

Откройте CMD в папке проекта:

```cmd
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
if not exist .env copy .env.example .env
notepad .env
```

Если файла `market.session` ещё нет, один раз авторизуйте пользовательский аккаунт:

```cmd
.venv\Scripts\python.exe parser\create_session.py
```

Для обычного запуска:

```cmd
.venv\Scripts\python.exe parser\catalog_bot.py --log-file tracker.log
```

Для хостинга через Планировщик заданий Windows создайте задачу **NFT Gift Tracker**. Выберите запуск при старте системы и выполнение независимо от входа пользователя. В действии укажите полный путь к `.venv\Scripts\python.exe`, аргументы `parser\catalog_bot.py --log-file tracker.log` и папку проекта в поле **Рабочая папка**. В параметрах выберите **Не запускать новый экземпляр** и отключите ограничение времени работы. Запускайте задачу от пользователя с доступом к проекту и сети. Лог появится в `tracker.log`. [Документация планировщика Windows](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtaskaction)

## Linux

В Debian или Ubuntu установите Python и поддержку виртуальных окружений:

```bash
sudo apt update
sudo apt install python3 python3-venv
```

В папке проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
test -f .env || cp .env.example .env
chmod 600 .env
nano .env
```

Если файла `market.session` ещё нет, авторизуйте аккаунт в консоли:

```bash
.venv/bin/python parser/create_session.py
chmod 600 market.session
```

Ручной запуск:

```bash
.venv/bin/python parser/catalog_bot.py
```

Для постоянного запуска создайте `/etc/systemd/system/nft-gift-tracker.service`. В примере проект расположен в `/opt/nft-gift-tracker`. Замените путь и имя `nfttracker` на свои. Указанный пользователь должен владеть файлами проекта, сессии и базы и иметь право писать в папку.

```ini
[Unit]
Description=NFT Gift Tracker
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
User=nfttracker
WorkingDirectory=/opt/nft-gift-tracker
ExecStart=/opt/nft-gift-tracker/.venv/bin/python /opt/nft-gift-tracker/parser/catalog_bot.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

После сохранения файла и остановки ручного экземпляра:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now nft-gift-tracker
sudo systemctl status nft-gift-tracker
sudo journalctl -u nft-gift-tracker -f
```

Для применения новой конфигурации запустите `sudo systemctl restart nft-gift-tracker`. Боту требуется исходящий доступ к Telegram и Crypto Pay. Входящий HTTP-порт для проверки платежей не нужен.

## Первый запуск

Откройте бота в Telegram и отправьте `/start`. Из аккаунта администратора откройте `/live`, чтобы проверить каталог и прогресс обхода. Команда `/group` настраивает форум и его ветки. Для проверки регистрации и доступа отправьте `/start` из обычного аккаунта.

## Оплата через Crypto Pay

Новый пользователь на `/start` видит пробный период на 15 минут в день по МСК и кнопку оплаты абонемента. Тарифы — 1 день за 1,5 TON, 3 дня за 4 TON и 7 дней за 10 TON. После выбора тарифа бот присылает в личку кнопку **Оплатить**, которая открывает счёт в Crypto Bot.

Доступ к каталогу и форуму получают администраторы, пользователи из белого списка и участники с действующей подпиской или пробным периодом. Бот проверяет заявки в группу по Telegram ID и удаляет участников по истечении доступа. После продления можно подать новую заявку.

Администраторы из `ADMIN_ID` могут проверить доступ пользователя, заблокировать или разблокировать его и изменить белый список через `/admin`.

### Проверка оплаты

Команда сверяет до 100 последних счетов из локальной базы с Crypto Pay и показывает, сколько счетов оплачено и скольким начислен доступ. Её можно выполнить в отдельной консоли при работающем боте.

Windows:

```cmd
.venv\Scripts\python.exe parser\catalog_bot.py --check-payments
```

Linux:

```bash
.venv/bin/python parser/catalog_bot.py --check-payments
```

Для полной проверки создайте счёт из обычного аккаунта, оплатите его в выбранной сети и дождитесь сообщения об активации. Повторите команду. Для успешного теста должны увеличиться оба счётчика, **Оплачено по API** и **Доступ начислен**. В норме бот опрашивает API каждые 15 секунд. В testnet можно пройти этот сценарий без оплаты в основной сети.

## Данные маркета

В каталоге и уведомлениях видны лоты с подтверждённым `@username` владельца. Если маркет отдаёт подпись вида `@username`, бот сверяет номер подарка и ID владельца с публичными подарками профиля. Цены остальных лотов участвуют в расчёте флора. Звёздный рейтинг подгружается в фоне.

По умолчанию полный обход запускается снова через 10 минут после завершения. Параллельно лайв-опрос проходит первые страницы по коллекциям с паузой `TELEGRAM_LIVE_REQUEST_SECONDS` между запросами. Telegram сортирует эти страницы по времени последнего изменения цены. Пауза по FloodWait действует и на лайв, и на полный обход. При повторе курсора бот пробует другую сортировку. Если обход неполный, прошлые лоты сохраняются в базе. Лот может измениться после проверки. База `catalog.sqlite3` хранит снимки, форум и журнал между запусками.

Каждая страница сохраняется сразу. После перезапуска каталог открывается из SQLite, а незавершённый обход возрастом до 24 часов пропускает уже полностью пройденные разделы. Коллекция, на которой остановился бот, проверяется снова.

Карточки используют анимированные эмодзи. Их ID можно переопределить в `.env`. Если Telegram запрещает кастомные эмодзи в чате, бот использует обычные.

Для пользовательской сессии можно задать `TELEGRAM_PROXY=socks5://user:password@host:port` в `.env`. Поддерживаются HTTP, SOCKS4 и SOCKS5.
